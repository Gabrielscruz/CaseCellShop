## 2. Prova de Fogo contra Overselling (`test/concurrency.spec.ts`)

### 2.1. O Cenário de Estresse
* **Estoque Físico Inicial:** Exatamente **10 unidades** de um produto de alta demanda (ex: *Capinha Silicone iPhone 15 Pro*).
* **Carga de Teste:** **100 requisições de checkout simultâneas** disparadas no mesmo milissegundo através de `Promise.all`:
  ```typescript
  const requests = Array.from({ length: 100 }).map((_, index) =>
    service
      .processCheckout({
        customerId: `customer-${index}`,
        items: [{ productId: mockProduct.id, quantity: 1 }],
      })
      .then((res) => ({ status: res.status, error: null }))
      .catch((err) => ({
        status: err instanceof ConflictError ? 'REJECTED' : 'ERROR',
        error: err.message,
      })),
  );

  const results = await Promise.all(requests);
  ```

### 2.2. Resultados Aferidos
* **Requisições Aprovadas (`HTTP 202 Accepted`):** Exatamente **10 requisições** conseguiram reservar o produto.
* **Requisições Rejeitadas com Conflito (`HTTP 409 Conflict`):** Exatamente **90 requisições** foram rejeitadas por falta de estoque (`Insufficient stock for product...`).
* **Erros Inesperados ou Inconsistências:** **0 erros** (`expect(errors.length).toBe(0)`).
* **Saldo Final de Estoque no Banco:** Exatamente **0 unidades**.
* **Conclusão:** Garantia matemática de **Zero Overselling**.

## 3. Teste de Idempotência (`test/idempotency.spec.ts`)

### 3.1. Cenário de Retries de Rede
* O cliente envia uma requisição de checkout com uma chave `x-idempotency-key` única.
* A primeira requisição é processada com sucesso, gerando um pedido `ord-123` e debitando o estoque de 10 para 9.
* A segunda requisição idêntica chega 100ms depois (simulando um retry automático do navegador ou clique duplo do usuário):
  ```typescript
  const secondResult = await service.processCheckout(dto, key);
  ```

### 3.2. Validações Confirmadas
1. O segundo resultado retorna exatamente a mesma resposta:
   `expect(secondResult.orderId).toBe('ord-123')`.
2. O método de baixa de estoque (`decrementStockAtomic`) é chamado **apenas 1 vez**:
   `expect(mockProductRepo.decrementStockAtomic).toHaveBeenCalledTimes(1)`.
3. O saldo remanescente permanece em **9 unidades**, sem duplicar o débito.

## 4. Testes de Resiliência de Cache (`test/redis-cache.spec.ts`)

1. **Teste de Cache Hit:** Valida que requisições subsequentes não chamam o banco e retornam `x-cache-status: HIT`.
2. **Teste de Prevenção de Stampede:** Simula duas threads concorrentes tentando ler um cache frio; valida que apenas uma thread executa o loader e a segunda reutiliza o dado aquecido após breve espera de 80ms.
3. **Teste de Fallback Gracioso:** Simula erro fatal no PostgreSQL (`PostgreSQL Connection Timeout`); valida que o `RedisCacheService` intercepta o erro e serve a cópia de 24h com `cacheStatus: STALE`, impedindo que a vitrine fique fora do ar.

```bash

cd app

# 1. Executar todos os testes da aplicação (unitários, integração e concorrência)
npm test

npm run test:concurrency

# 3. Executar com cobertura de código (Coverage Report)
npm run test:cov
```
