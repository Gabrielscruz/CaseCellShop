# 🏛️ Arquitetura do Sistema e Princípios SOLID

Este documento descreve as decisões arquiteturais fundamentais adotadas no **CaseCellShop**, a divisão de camadas baseada em **Clean Architecture / DDD** e a aplicação prática de cada princípio **SOLID**.

---

## 1. Visão Geral da Arquitetura

O sistema adota uma abordagem de **Monólito Modular** orientado a domínio, desacoplado em camadas estritas através do princípio de **Inversão de Dependência (DIP)**:

```text
┌─────────────────────────────────────────────────────────────┐
│                    Transporte & Ingress                     │
│    Controllers HTTP (NestJS), Swagger / OpenAPI, AMQP       │
└──────────────────────────────┬──────────────────────────────┘
                               │ (DTOs / Request)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                     Camada de Aplicação                     │
│         Services (Orquestração de Casos de Uso)             │
│    ProductsService, OrdersService, OrdersConsumer (Worker)  │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                       Domínio Puro                          │
│          Entidades de Negócio, Interfaces de Repositório    │
│                  Hierarquia de AppErrors                    │
└──────────────────────────────▲──────────────────────────────┘
                               │
         (Inversão de Dependência via Interfaces / Ports)     │
                               │
┌──────────────────────────────┴──────────────────────────────┐
│                    Infraestrutura & Adapters                │
│    Prisma ORM (Postgres), Redis (Cache & Lock), RabbitMQ    │
│            Structured Logger (Pino), Prometheus             │
└─────────────────────────────────────────────────────────────┘
```

## 2. Princípios SOLID Aplicados na Prática

### 2.1. S — Single Responsibility Principle (Princípio da Responsabilidade Única)
Cada classe e módulo possui um único propósito bem definido:
* **Controllers ([`products.controller.ts`](file:///home/gabriel/Documentos/CaseCellShop/app/src/modules/products/products.controller.ts), [`orders.controller.ts`](file:///home/gabriel/Documentos/CaseCellShop/app/src/modules/orders/orders.controller.ts)):** Cuidam estritamente da camada de transporte HTTP (recepção de DTOs, cabeçalhos e códigos de status HTTP). Não contêm lógica de negócio.
* **Services ([`orders.service.ts`](file:///home/gabriel/Documentos/CaseCellShop/app/src/modules/orders/orders.service.ts), [`products.service.ts`](file:///home/gabriel/Documentos/CaseCellShop/app/src/modules/products/products.service.ts)):** Concentram as regras de negócio puras (baixa de estoque, orquestração de idempotência e disparo de eventos). Desconhecem o protocolo HTTP.
* **Repositories ([`prisma-product.repository.ts`](file:///home/gabriel/Documentos/CaseCellShop/app/src/infra/database/prisma-product.repository.ts), [`prisma-order.repository.ts`](file:///home/gabriel/Documentos/CaseCellShop/app/src/infra/database/prisma-order.repository.ts)):** Responsáveis unicamente pela persistência e consultas ao banco de dados via Prisma.
* **Consumer ([`orders.consumer.ts`](file:///home/gabriel/Documentos/CaseCellShop/app/src/infra/messaging/orders.consumer.ts)):** Atua como background worker para a esteira assíncrona, simulando o ERP e executando a compensação SAGA em falhas.

### 2.2. O — Open/Closed Principle (Princípio Aberto/Fechado)
* **Desacoplamento de Erros via Hierarquia:** A classe base abstrata [`AppError`](file:///home/gabriel/Documentos/CaseCellShop/app/src/core/errors/app.error.ts) é estendida por erros semânticos de domínio (`ConflictError`, `NotFoundError`, `BadRequestError`).
* **Interceptors Extensíveis:** O [`ErrorHandlerInterceptor`](file:///home/gabriel/Documentos/CaseCellShop/app/src/common/interceptors/error-handler.interceptor.ts) trata as classes base. Se novos erros forem adicionados (ex: `PaymentGatewayTimeoutError`), basta estender a classe base apropriada sem precisar modificar a lógica central do interceptor.

### 2.3. L — Liskov Substitution Principle (Princípio da Substituição de Liskov)
* As implementações de repositório ([`PrismaProductRepository`](file:///home/gabriel/Documentos/CaseCellShop/app/src/infra/database/prisma-product.repository.ts) e [`PrismaOrderRepository`](file:///home/gabriel/Documentos/CaseCellShop/app/src/infra/database/prisma-order.repository.ts)) implementam integralmente os contratos definidos em [`IProductRepository`](file:///home/gabriel/Documentos/CaseCellShop/app/src/core/products/product.repository.interface.ts) e [`IOrderRepository`](file:///home/gabriel/Documentos/CaseCellShop/app/src/core/orders/order.repository.interface.ts).
* Nos testes de unidade e concorrência (`test/concurrency.spec.ts`), repositórios mockados em memória substituem 100% o comportamento das classes concretas sem necessidade de mocks de banco complexos.

### 2.4. I — Interface Segregation Principle (Princípio da Segregação de Interfaces)
* Nenhuma interface do sistema obriga seus consumidores a implementar métodos que não utilizam.
* A interface [`IProductRepository`](file:///home/gabriel/Documentos/CaseCellShop/app/src/core/products/product.repository.interface.ts) expõe métodos atômicos focados (`findPaginated`, `findById`, `decrementStockAtomic`, `incrementStockAtomic`), segregada do repositório de pedidos ([`IOrderRepository`](file:///home/gabriel/Documentos/CaseCellShop/app/src/core/orders/order.repository.interface.ts)).

### 2.5. D — Dependency Inversion Principle (Princípio da Inversão de Dependência)
* Os módulos de alto nível (casos de uso nos Services) não dependem de módulos de baixo nível (Prisma ORM ou drivers de banco). Ambos dependem de abstrações (Interfaces/Ports) localizadas no diretório [`src/core/`](file:///home/gabriel/Documentos/CaseCellShop/app/src/core/).
* **Injeção de Dependências com Symbols:**
  ```typescript
  constructor(
    @Inject(ORDER_REPOSITORY)
    private readonly orderRepo: IOrderRepository,
    @Inject(PRODUCT_REPOSITORY)
    private readonly productRepo: IProductRepository,
  ) {}
  ```
  Isso desacopla completamente a regra de negócio do provedor de dados, permitindo trocar o Prisma por TypeORM, Kysely ou Drizzle sem alterar uma única linha de regra de negócio.

## 3. Estrutura de Pastas Detalhada

```text
app/src/
├── app.module.ts                         # Módulo raiz com registro de middlewares globais
├── main.ts                               # Bootstrap com Swagger, Validação e Filtros Globais
│
├── core/                                 # 🏛️ CAMADA DE DOMÍNIO PURO (Zero dependência de frameworks)
│   ├── products/
│   │   ├── product.entity.ts             # Interface da entidade Produto
│   │   └── product.repository.interface.ts # Contrato do repositório e DTO de paginação
│   ├── orders/
│   │   ├── order.entity.ts               # Entidade Pedido e Enum de OrderStatus
│   │   └── order.repository.interface.ts # Contrato do repositório de Pedidos
│   └── errors/
│       ├── app.error.ts                  # Classe base para erros de negócio
│       ├── conflict.error.ts             # Conflitos de concorrência e estoque insuficiente
│       ├── not-found.error.ts            # Entidades inexistentes no catálogo
│       └── bad-request.error.ts          # Parâmetros e cursores inválidos
│
├── modules/                              # 📦 CASOS DE USO E TRANSPORTE (NestJS)
│   ├── products/
│   │   ├── products.module.ts            # Registro do módulo e DI
│   │   ├── products.controller.ts        # GET /products com cabeçalhos de cache
│   │   ├── products.service.ts           # Orquestração de busca com Cache-Aside
│   │   └── dto/
│   │       └── find-products.dto.ts      # Validação de limit (1-1000) e cursor
│   └── orders/
│       ├── orders.module.ts              # Registro do módulo e DI
│       ├── orders.controller.ts          # POST /checkout (202) e GET /orders/:id/status
│       ├── orders.service.ts             # Checkout, baixa atômica e idempotência
│       └── dto/
│           └── checkout.dto.ts           # Validação UUID v4, itens e carrinho
│
├── common/                               # 🛡️ INTERCEPTORS E EXCEPTION FILTERS
│   ├── interceptors/
│   │   └── error-handler.interceptor.ts  # Desacoplamento Domínio/Prisma ➔ HttpException
│   └── filters/
│       └── global-exception.filter.ts    # JSON padronizado com correlationId e severidade
│
├── infra/                                # ⚙️ ADAPTERS DE INFRAESTRUTURA
│   ├── database/
│   │   ├── database.module.ts            # Provedores e injeção com Symbol tokens
│   │   ├── prisma.service.ts             # Conexão resiliente e adapter pg
│   │   ├── prisma-product.repository.ts  # Baixa atômica e paginação por índice
│   │   └── prisma-order.repository.ts    # Criação e atualização de pedidos
│   ├── cache/
│   │   ├── cache.module.ts               # Registro do Redis Client
│   │   ├── redis.client.ts               # Conexão nativa ioredis
│   │   └── redis-cache.service.ts        # Cache-Aside, Anti-Stampede Lock e Fallback
│   ├── messaging/
│   │   ├── messaging.module.ts           # Registro do RabbitMQ e Consumer
│   │   ├── rabbitmq.service.ts           # Topologia AMQP, Direct Exchange e DLQ
│   │   └── orders.consumer.ts            # Worker em background com Padrão SAGA
│   └── observability/
│       ├── observability.module.ts       # Módulo global de métricas e telemetria
│       ├── correlation-id.middleware.ts  # Injeção e propagação de AsyncLocalStorage
│       ├── metrics.middleware.ts         # Cálculo de latência HTTP e contagem de QPS
│       ├── metrics.service.ts            # Registro Prom-Client (Histograms, Counters)
│       ├── metrics.controller.ts         # Endpoint /metrics (OpenMetrics)
│       ├── health.controller.ts          # Endpoint /health (Postgres + Redis check)
│       └── logger.service.ts             # Structured Logger com formato JSON Pino
│
└── utils/                                # 🧰 UTILITÁRIOS PUROS
    ├── cursor.util.ts                    # Codificação/Decodificação Base64URL segura
    ├── cache.util.ts                     # Construtor semântico de chaves Redis
    └── time.util.ts                      # Helpers de delay e tempo assíncrono
```
